# Gomoku v1.4.0 · 大厅一键加入等待中的房间

版本 `1.4.0+10400`。私有服务器上两三个人开黑，不该再把六位房间码发来发去——大厅现在直接列出等待对手的房间，点一下就进。

- **一键加入**:大厅新增"等待中的房间"区，显示"{昵称} 在等你加入"和加入按钮，每 5 秒自动刷新。客户端每 5 秒轮询一次只读的 `room.openRooms` 接口；离线或未登录时列表为空、区块隐藏，不影响原有流程。
- **服务端规则**:只列出guest席位空闲的 waiting 房间（复赛等待的房间不会出现）、更新时间在 30 分钟等待期内、排除调用者自己的房间；房主昵称从 `gm_players` 实时读取，改名后列表也显示新昵称；每人每分钟限 60 次轮询，最多返回 20 条。旧客户端不调用该接口，行为不变；新客户端连旧服务器时列表自动隐藏。
- **房间码仍然保留**:分享给列表之外的朋友（微信贴码、邀请链接）照旧可用，两种方式并存。

验证:静态分析与格式化零问题；客户端 50 项测试（新增大厅列表与空态 2 项）与服务端 17 项系统测试（新增 openRooms 列表、隐藏自身、满座退出列表 3 项断言；真实 PostgreSQL、Redis、Mailpit）全部通过。六端客户端与 Debian 12 服务端构建由标签流水线执行，全部成功后才发布。协议变更由 serverpod_cli 3.4.13 生成，无数据库迁移。

Android 使用既有正式证书，versionCode 10400，可直接覆盖安装前序版本;Windows 解压后运行 `Gomoku.exe`;macOS 未公证;iOS 包未签名。

服务端升级使用 `manage.py install Gomoku-1.4.0-server-debian12-x64.tar.gz`（Docker 部署则更新镜像后 `docker compose up -d`）。无新增迁移，升级即回滚安全;账号体系与 v1.3.0 相同。
