# Gomoku v1.3.0 · 登录统一为邮箱账户

版本 `1.3.0+10300`。账户页不再出现"账号 1 / 账号 2"选择卡与 8 位数字密码提示——该分支还曾把缺失的文案键名（如 `loginName`）直接渲染到页面上。现在所有部署只用一套登录方式。

- **邮箱登录**:账户页只保留 登录、注册、忘记密码 的邮箱流程，并补上此前缺失的页头。服务端登录只接受邮箱+密码，历史短别名 `1`、`2` 不再是登录名。
- **私有模式移除**:`GOMOKU_AUTH_MODE` 环境变量废弃。旧部署的预置账号本来就是邮箱账户（`player1@域名`、`player2@域名`），升级后直接用邮箱+密码登录，无需迁移;管理员预置与改密命令保留（`reset-password` 仍接受别名 `1`、`2` 指代预置账号）。
- **升级兼容**:新版客户端连接尚未升级的服务器时，回退为纯邮箱登录并隐藏注册/重置入口；旧版客户端连接新服务器不受影响。
- **其他**:大厅页移除私有登录门槛;修正设置页"关于"中英文版本号不一致的问题。

验证:静态分析与格式化零问题;核心规则 12 项、客户端 48 项（含重写的邮箱登录流测试）与服务端 16 项系统测试（真实 PostgreSQL、Redis、Mailpit）全部通过;本地开发栈实测邮箱登录、错误密码拒绝、旧别名拒绝，并经浏览器截图复核账户页与登录后状态。六端客户端与 Debian 12 服务端构建由标签流水线执行，全部成功后才发布。

Android 使用既有正式证书，versionCode 10300，可直接覆盖安装前序版本;Windows 解压后运行 `Gomoku.exe`;macOS 未公证;iOS 包未签名。

服务端升级使用 `manage.py install Gomoku-1.3.0-server-debian12-x64.tar.gz`。升级后账号密码从服务器 `/etc/gomoku/initial-accounts.json` 查看并交付;注册与忘记密码的验证码邮件需要配置 `runtime.env` 的 `SMTP_*`，未配置 SMTP 的部署继续由管理员预置账号。建议升级完成后按 [原生部署方案](../NATIVE_DEPLOYMENT.md#容量验收) 复核线上与容量验收。
